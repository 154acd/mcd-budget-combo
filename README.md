# 麦当劳预算饱腹搭配 · mcd-budget-combo

> 给出位置和预算，自动找到附近麦当劳门店，结合各门店**真实可用优惠券**与在售菜单，通过官方 `calculate-price` 接口逐一真实核价，输出预算内**最饱腹、件数最多、经典省钱、用券多吃**等多种搭配方案。

基于麦当劳中国官方 MCP Server（mcd-mcp）的 WorkBuddy Skill。麦当劳程序员创意开发大赛参赛作品。

## 它解决什么问题

你来到一个陌生地点，兜里预算有限（默认 30 元），想吃麦当劳吃饱。难点不是没有信息，而是信息有三层「陷阱」：

1. **门店差异**：同一条街的几家麦当劳，菜单和券并不一样（实测同区域 3 家门店中，「精选超值随心配」13.9 元只有 2 家在售）；
2. **券面 ≠ 实惠**：券的使用门槛、渠道、指定商品都会影响真实优惠——实测某账户 2 张「新人专享 7 折券」按名称看都能用，按商品编码实测**都不可用**（适用商品不在门店菜单）；
3. **价格必须真算**：目录价不等于到手价，配送费、打包费、券后价只有官方核价接口说了算。

这个 Skill 把「找店 → 查券 → 查菜单 → 枚举搭配 → 真实核价 → 输出报告」压缩成**一轮对话**。

## 效果示例（真实调用输出，2026-10-12 实测）

用户：「我在深圳南山，只有 10 元，附近麦当劳能吃什么？」

```
【门店 1】麦当劳深圳桂庙路餐厅 · 71m · 营业中（00:00–23:59）· 当前为夜市时段

可用优惠券（query-store-coupons 实时查询）：
- 新人专享-中杯美式7折 —— 暂不可用（适用商品编码 9900000119 不在本店菜单）
- 新人专享-中杯奶铁7折 —— 暂不可用（适用商品编码 9900000117 不在本店菜单）

搭配方案（预算 10 元；价格均为 calculate-price 实时核价）：
A. 最饱腹｜无（10 元内没有含主食的套餐可选；最便宜主食单品「牛肉堡单品精选」目录价 14.00 元，还差 4.00 元）
B. 件数最多｜圆筒冰淇淋 ×2 —— 约 2 件，核价 10.00 元，余 0.00 元
C. 经典省心｜圆筒冰淇淋 ×1 —— 约 1 件，核价 5.00 元，余 5.00 元
D. 用券多吃｜无（本店可用券的适用商品均不在菜单 / 暂无可用券）

差额建议（目录价，下单前以实时核价为准）：
- 加 4.90 元（总 14.90 元）→ 人气经典随心配（2 件：主食+小食/饮料任选）
- 加 3.90 元（总 13.90 元）→ 精选超值随心配（2 件），仅该店有售

提示：回复「领券」可查看并领取优惠券；确定方案后可说「就点 B 方案」（下单前会复述订单与金额，经你确认后才提交）。
```

30 元标准场景下，实测输出三门店对比，每店 A/B/C 三档方案（如「大堡口福三件套 + 圆筒冰淇淋 = 27.9 元 / 4 件含 1 份主食」「精选超值随心配 + 圆筒×2 + 灰焰圆筒 = 28.9 元 / 5 件」）。

## 特性

- **真实核价**：所有方案价格来自官方 calculate-price 接口逐一计算，拒绝「券面额估算」；
- **门店级用券**：以 query-store-coupons 为唯一权威来源，按 productCode 精确匹配（避开「同名不同码」坑），券商品不在售时明确标注；
- **多策略搭配**：最饱腹 / 件数最多 / 经典省心 / 用券多吃四模板枚举，本地零依赖脚本计算，agent 只负责核价；
- **位置零门槛**：说「南山」可以，直接粘贴高德/百度复制的完整地址行也可以（实测 13m 精度，MCP 服务端自带地理编码）；
- **只读安全**：默认不碰账户写操作；领券 / 下单 / 存地址必须「明确指令 → 复述内容与金额 → 用户确认」三步走；
- **外送适配**：麦乐送场景自动走地址簿 → 可配送门店 → orderType=2 链路，配送费先从预算扣除，占比过高时建议到店自取。

## 安装

### 1. 申请麦当劳 MCP Token

访问 https://open.mcd.cn/mcp → 手机号验证码登录 → 右上角「控制台」→「激活」→ 复制 Token。

### 2. 配置 MCP 连接

在 MCP 客户端（以 WorkBuddy 为例：【连接器】→【自定义连接器】→【配置 MCP】）中填入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

把 `${MCD_MCP_TOKEN}` 替换为实际 Token 并启用连接器。（本仓库 mcp-config.example.json 为同内容脱敏示例。）

### 3. 安装 Skill

把本仓库整体放入技能目录（仓库根目录即技能目录）：

```bash
# WorkBuddy（用户级技能目录）
cp -r mcd-budget-combo ~/.workbuddy/skills/mcd-budget-combo
```

其他支持 MCP 的客户端（Claude Code、Cursor、Cline、Cherry Studio 等）：将 SKILL.md 与 references/、scripts/、tests/ 放入各自技能目录即可，SKILL.md 与参考资料全程使用官方工具名（query-meals、calculate-price 等），不绑定特定框架。

安装后直接用自然语言提问：

- 「我在深圳南山，预算 30 元，怎么吃最饱？」
- 「我在广东省深圳市南山区南山大道1175号新绿岛大厦，30 元怎么吃」（地图复制的地址直接贴）
- 「30 元点麦乐送送到家」
- 「这店有什么券？帮我领券」（会先列出并复述，确认后才领取）

## 目标用户

- **价格敏感型干饭人**：预算固定，想把每一块钱换成最多的饱腹感；
- **异地差旅 / 刚到新城市的人**：不熟悉周边门店，一句话获得「去哪家、点什么」；
- **优惠券「用不明白」的人**：账户里一堆券不知道哪张在哪家店真能用；
- **Any AI 客户端用户**：技能以官方 MCP 工具名描述流程，可接入任何支持 MCP 的框架。

## 使用的 MCP 工具

只读：`query-nearby-stores`、`query-store-coupons`、`query-meals`、`calculate-price`、`now-time-info`、`available-coupons`、`query-my-coupons`、`list-nutrition-foods`、`delivery-query-addresses`、`delivery-query-stores`、`query-meal-detail`、`cancel-order`（仅补救）

条件写（三重确认后才调用）：`auto-bind-coupons`、`create-order`、`delivery-create-address`

明确不使用：积分商城 / 抽奖 / 派对预订 / 团餐等场景工具（原因见 MCP_INTEGRATION.md 第 2.3 节）

## 已知限制

- **外送链路未端到端实测**：测试账户地址簿为空，配送费探针逻辑按官方参数矩阵实现但未跑通真实订单前置流（详见 MCP_INTEGRATION.md 第 4.5 节）；
- **千卡为参考值**：套餐 / 随心配的内部构成需展开查询，未展开时千卡字段不展示，不做估算；
- **数据时效性**：餐品、价格、券以麦当劳官方实时结果为准；搭配报告中的「约 N 件」为按菜单结构的估算值；
- **本 Skill 不代替用户决策**：输出为搭配建议，是否下单由用户确认后执行。
